# v0.1 — Transparent proxy

Implements a JSON-RPC proxy that forwards all traffic between the IDE and a downstream TS LSP subprocess without modification. No Bun-specific behaviour. Establishes that the proxy architecture is sound.

**Done when:** substituting `bundt` for the downstream TS LSP in any LSP client produces identical editor behaviour.

---

## Stories in scope

| Story | Summary                                                           |
| ----- | ----------------------------------------------------------------- |
| US-12 | Full LSP feature parity via transparent forwarding                |
| US-13 | No measurable latency added by the proxy layer                    |
| US-26 | Clear error when the downstream TS LSP binary is not found        |
| US-27 | Recovery via the editor's standard LSP restart if proxy/LSP exits |
| US-28 | Malformed JSON-RPC messages are logged and skipped, not fatal     |

---

## Crate structure

```
bundt/
  Cargo.toml
  src/
    main.rs      — CLI parsing, subprocess spawn, shutdown wiring
    framing.rs   — LSP Content-Length frame read/write
    router.rs    — bidirectional forward loop (expanded in v0.2+)
```

`router.rs` is introduced now at its final name. In v0.1 it only forwards. v0.2 will add interception logic to the same module.

---

## Dependencies

| Crate        | Use                                                                       |
| ------------ | ------------------------------------------------------------------------- |
| `tokio`      | Async runtime; `process`, `io-util`, `rt-multi-thread`, `macros` features |
| `serde_json` | JSON validation for malformed-frame detection (US-28)                     |
| `anyhow`     | Error propagation                                                         |

No LSP crate is needed in v0.1 — frames are forwarded as raw bytes. `serde_json` is only used to validate that a frame body is parseable JSON before forwarding.

### Step 3 — LSP frame read/write (`framing.rs`) (US-28) ✅ Done

LSP framing: `Content-Length: N\r\n\r\n` followed by N UTF-8 bytes.

- [x] `async fn read_frame(reader: &mut impl AsyncBufRead) -> Result<Option<Vec<u8>>>` — returns `None` on clean EOF
  - Reads header lines until blank line
  - Extracts `Content-Length` value; returns `Err` if header is missing or non-numeric
  - Reads exactly N bytes as the body
- [x] `async fn write_frame(writer: &mut impl AsyncWrite, body: &[u8]) -> Result<()>` — writes the header and body

**Unit tests** (in `framing.rs`)
- Valid frame written then read back returns the original bytes unchanged
- Clean EOF (empty reader) returns `None`
- EOF mid-header returns `Err`
- Missing `Content-Length` header returns `Err`
- Non-numeric `Content-Length` value returns `Err`
- `Content-Length` larger than available bytes returns `Err`
- Multiple frames written and read back in sequence all round-trip correctly

### Step 4 — Bidirectional forward loop (`router.rs`) (US-12, US-13, US-28) ✅ Done

- [x] `pub async fn run(ide_in, ide_out, lsp_in, lsp_out) -> Result<()>`
- [x] Spawn two concurrent tasks using `tokio::try_join!`:
  - **IDE → LSP**: read frame from `ide_in`; validate body is parseable JSON (log + skip on error, US-28); write frame to `lsp_in`
  - **LSP → IDE**: read frame from `lsp_out`; validate body is parseable JSON (log + skip on error, US-28); write frame to `ide_out`
- [x] Either direction reaching clean EOF terminates both tasks (ownership: dropping `lsp_in` when IDE→LSP direction completes closes the downstream pipe, causing the LSP to exit and unblocking the LSP→IDE direction)
- [x] No buffering beyond what `tokio::io::BufReader` provides — frames are written as soon as read (US-13)

**Unit tests** (in `router.rs`, using `tokio_test` or in-memory duplex streams)
- A single valid frame sent IDE→LSP arrives at the LSP side byte-for-byte unchanged
- A single valid frame sent LSP→IDE arrives at the IDE side byte-for-byte unchanged
- A malformed JSON frame (valid framing, invalid JSON body) in the IDE→LSP direction is skipped; subsequent valid frames still flow through
- A malformed JSON frame in the LSP→IDE direction is skipped; subsequent valid frames still flow through
- EOF on IDE input causes `run` to return after draining any in-flight frames

**Integration tests** (`tests/proxy.rs`)
- Spawn `bundt cat` (or a trivial echo subprocess); send 3 well-formed LSP frames to bundt stdin; verify all 3 arrive unchanged on bundt stdout
- Inject one malformed JSON frame between two valid frames; verify the two valid frames still arrive and bundt does not exit non-zero

**Manual verification**
- Use the helper script below to send a single frame and observe it echoed back:
  ```bash
  printf 'Content-Length: 2\r\n\r\n{}' | ./target/debug/bundt cat
  ```
  Expected: `Content-Length: 2\r\n\r\n{}` printed to stdout; bundt exits 0.

### Step 5 — Shutdown (US-27) ✅ Done

- [x] After the forward loop exits (IDE EOF or LSP exit), close the LSP stdin pipe and call `child.wait()`
- [x] If the subprocess exits unexpectedly (detected when the LSP→IDE task gets EOF): log the exit status to stderr; exit `bundt` with the same exit code (US-27)
- [x] Exit code 0 on clean shutdown (IDE-initiated)

**Integration tests** (`tests/proxy.rs`)
- Spawn `bundt` wrapping a subprocess that exits with code 42 immediately after receiving one frame; verify bundt also exits with code 42 and logs the exit status to stderr
- Send EOF to bundt stdin while the subprocess is idle; verify bundt exits with code 0

**Manual verification**
- `echo '' | ./target/debug/bundt cat` — cat exits when stdin closes; verify bundt also exits 0
- `./target/debug/bundt sh -c 'exit 7'` — subprocess exits immediately with 7; verify bundt stderr mentions the exit status and bundt exits 7
